# Privacy review checklist

BUILD_PLAN Phase 9.1. Each item lists what the product does and the automated check that proves
it. Run everything with `pnpm test` (unit + API integration) and `pnpm test:e2e` (browser suites).
Re-run this review before every release and whenever capture, upload or storage code changes.

## Open items for the pilot

- Legal review of the region defaults in `apps/api/src/regions.ts` (retention caps, valid notice versions) per deployment.
- Face matching (Phase 11) is biometric processing: before an organisation enables it, a DPIA (GDPR/UK GDPR Art. 9 and 35, Nigeria NDPA 2023 sensitive data) or the local equivalent (e.g. Illinois BIPA written policy), and a decision on whether consent can be freely given in an exam setting. The face-matching notice version is accepted in every region by default; remove it from a region in `regions.ts` to refuse it there.
- Face matching accuracy and fairness are not measured on real candidates; the harness (`e2e/fairness/face-match.spec.ts`) uses three people in studio portraits. See `docs/FAIRNESS.md` before enabling it.
- Whether the reference face was actually formed on the device is not reported to the server (only the opt-in is), so a report cannot distinguish "matched throughout" from "no reference taken".
- A consented, labelled fairness dataset (skin tone, glasses, disability-related movement); see `docs/FAIRNESS.md`.
- Data processing agreement and the organisation's own privacy notice (template: `docs/privacy-policy.md`).
